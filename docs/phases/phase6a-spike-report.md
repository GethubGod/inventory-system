# Phase 6a — screenshot parse spike report

Status: complete (synthetic-only). Go/adjust decision input for 6b.

IMPORTANT: **GEMINI_API_KEY was not available in this environment, so no real
model call was made.** All accuracy numbers below are **SYNTHETIC/SIMULATED**:
they were produced by running `score.mjs` against hand-written "plausible
Gemini 2.5 Flash parse" outputs (`scripts/spike/simulated/`) that encode an
ideal parse plus typical error modes for this model family. They demonstrate
the measurement harness and the expected error surface, not measured model
performance. **Real-screenshot validation is on NEEDS-DAVID** (see bottom).

## Method

1. **Prototype parser** — `scripts/spike/parse-order-screenshot.mjs` (zero npm
   deps, Node built-ins only). It mirrors the repo's existing Gemini plumbing
   in `supabase/functions/quick-order-voice-parse/index.ts` exactly:
   - REST `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`
     with the `x-goog-api-key` header (`GEMINI_API_KEY`, `GOOGLE_API_KEY` fallback);
   - `generationConfig { temperature: 0.1, responseMimeType: 'application/json', responseSchema }`
     for schema-constrained JSON;
   - the image as an `inlineData` base64 part (the voice fn does the same with audio);
   - 30 s timeout, 2 attempts with the same "return strict JSON" retry nudge,
     and the same lenient JSON re-extraction (`parseGeminiJson` pattern).

   Output contract: `{ items: [{ name, quantity, unit, note? }] }` — name
   verbatim-as-written (no canonicalization at extraction time), quantity
   number-or-null (ranges → upper bound + note), unit normalized to a small
   vocabulary or null, struck-through/cancelled lines skipped.
   `--dry-run` prints prompt + schema + would-be request without calling.

2. **Synthetic fixtures** — `scripts/spike/fixtures/`: 8 PNGs + per-image
   ground truth (`*.gt.json`), generated by `scripts/spike/gen-fixtures.mjs`.
   Method: the script emits SVG (committed alongside) and converts to PNG with
   the macOS built-in QuickLook thumbnailer (`qlmanage -t -s 1280`), which
   renders system fonts including CJK — no npm image libraries, root
   `package.json` untouched. Formats covered: clean numbered list, texting
   shorthand (`2 cs salmon`, `nori x3`), mixed units incl. parenthetical pack
   size, quantity ranges (`2-3`, `5~6`, `1 or 2`), strikethrough + timestamp
   noise, mixed English/Chinese with a CJK unit (`箱`), ALL-CAPS/typos
   (`SAMON 2CS`, `MASSAGO`), and an iMessage-style chat thread with greeting
   noise. Renders were visually verified (strikethrough line, CJK glyphs, and
   chat bubbles all render correctly).

3. **Scorer** — `scripts/spike/score.mjs`: greedy name-similarity alignment of
   parsed vs ground-truth items, then item precision/recall, quantity accuracy
   and unit accuracy over aligned pairs, plus an inventory fuzzy-match pass of
   every parsed name against a 12-item mock catalog (names + aliases in the
   style of the seeded alias data in
   `supabase/migrations/20260510020000_quick_order_seed_data.sql`).
   Normalization replicated from the real infra (cited in the script header):
   - alias-key exact matching mirrors `normalize_quick_order_alias_text()` from
     `supabase/migrations/20260523120000_employee_quick_order_aliases.sql`
     (also the generated `alias_key` in `quick_order_alias_rules`,
     `supabase/migrations/20260525140000_quick_order_parser_rules_v2.sql`):
     lower + trim + collapse whitespace;
   - the fuzzy layer ports `normalizeCatalogText`, plural normalization, and
     `similarity` (edit distance + token Dice + Jaro-Winkler + prefix boost)
     from `supabase/functions/parse-order/catalog-search-index.ts`;
   - unit synonyms mirror `DEFAULT_UNIT_ALIASES` in
     `supabase/functions/parse-order/units.ts` (plus `tub`).

## Model + prompt recommendation

- **Model: `gemini-2.5-flash`** — the same default the repo already uses for
  voice parsing (`QUICK_ORDER_VOICE_MODEL ?? 'gemini-2.5-flash'`) and as the
  parse-order default/fallback tier in
  `supabase/functions/parse-order/model-router.ts`. Screenshot extraction is a
  simpler task than noisy-audio interpretation (text is literally printed in
  the image), so the flash tier should suffice; the router's advanced tier
  (`gemini-3.1-pro`) is the ready-made escalation if real screenshots (photos
  of handwriting, glare) underperform — the script takes `--model` for an A/B.
- **Prompt**: extraction-only, modeled on the voice fn's `buildPrompt()` rule
  style (explicit unit vocabulary, "do not invent", strict-JSON-only, range and
  strikethrough policies). Deliberately does NOT inject the inventory catalog:
  the spike measures raw extraction and matches separately. **For 6b, inject
  the catalog into the prompt exactly like the voice fn does** — it measurably
  helps the model resolve shorthand at parse time, and keep the DB-side
  alias/fuzzy match as the authoritative pass.
- **Schema-constrained JSON** (`responseSchema` + `responseMimeType`) worked
  well for the voice fn and is the right call here; keep the 2-attempt retry.

## Expected failure modes (encoded in the simulation; watch for on real images)

1. **Struck-through items not skipped** (05) — a crossed-out line gets
   extracted anyway → false positive. Mitigation: explicit prompt rule (done)
   plus the 6b review screen, where a spurious row is visible and deletable.
2. **Items dropped inside chat noise** (08) — a mid-sentence item ("mayo 1
   btl" inside a bubble with filler) is missed → recall loss. Highest-impact
   real risk; mitigate by prompting "one item per entry, read every bubble"
   and A/B `gemini-3.1-pro` on chat-style screenshots.
3. **Ranges taken at the wrong bound** (04) — "5~6 lb" → 5 instead of the
   agreed upper bound. Policy encoded in prompt + note field; review UI shows
   the note.
4. **CJK units left untranslated** (06) — `箱` kept instead of `case`.
   Cheap deterministic fix in 6b: extend the unit alias map (the
   `buildUnitAliases` extra-aliases hook in `parse-order/units.ts` already
   supports adding `箱 → cs`) rather than relying on the model.
5. **Shorthand units missed** (03) — `3 pk` parsed with unit null. Same
   deterministic backstop: unit aliasing on the raw line where available.
6. **Typos preserved by design** (07) — `samon`, `massago` are NOT extraction
   errors under this contract; the matching layer resolves them (see below).

## Inventory matching results (mock catalog, threshold 0.72)

| bucket | share |
|---|---|
| exact (alias-key normalization) | 29/33 (87.9%) |
| fuzzy (ported `similarity`) | 4/33 (12.1%) |
| unmatched → review UI | 0/33 (0.0%) |

Fuzzy hits: `samon → Salmon fillet` (0.956), `yellow tail → Yellowtail`
(0.96), `massago → Masago` (0.967) — all correct, showing the ported
similarity layer absorbs realistic typos/spacing.

**Real observed failure (in the spike itself, not simulated):**
`hondashi → Yellowtail` at 0.721 — a false fuzzy match landing exactly at the
0.72 threshold via Jaro-Winkler letter overlap. Hondashi was planted as the
"not in inventory" item and should have hit the review bucket. The production
matcher would reject this: `analyzeSemanticTokens` in
`supabase/functions/parse-order/catalog-search-index.ts` requires specific-token
coverage (`similarity ≥ 0.88` per token), which hondashi/yellowtail fails.
**Conclusion for 6b: do not match on raw `similarity` alone — reuse the full
`matchCatalogIndex`/semantic-gate pipeline from `parse-order`, or at minimum
auto-match only ≥ 0.80 and route 0.72–0.80 to "suggested" in the review UI.**

## Recommendation for 6b: GO (with adjustments)

GO on the planned architecture — the provider plumbing is proven in production
for a harder modality (noisy kitchen audio), schema-constrained JSON removes
the output-format risk, and the alias + fuzzy infra already absorbs the
realistic name noise. Adjustments to carry into 6b:

1. Inject the inventory catalog into the parse prompt (as the voice fn does),
   keeping raw `name` verbatim in `historical_order_import_items` for audit.
2. Match via the full `matchCatalogIndex` semantic-gated pipeline, not raw
   similarity; two-tier confidence (auto vs suggested) in the review screen.
3. Extend unit aliases deterministically (CJK units, `tub`) instead of
   trusting the model's unit normalization.
4. Keep `gemini-2.5-flash` default with a `gemini-3.1-pro` escalation knob;
   decide after the first real batch.
